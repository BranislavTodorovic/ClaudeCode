## Planned architecture delta, to freeze in R1.1

| Contract | R0 decision |
|---|---|
| Shell | One global header, primary world navigation, search/Quick Capture entry, utility access, accessible mobile navigation and consistent active-parent behavior. One selected world at a time. Reference nav labels/order do not override this contract. |
| Eight worlds | Canonical world IDs/order: `home`, `work`, `personal`, `explore`, `games`, `movies`, `projects-notes`, `settings`. Home’s Media & Games grouping leads to two separate worlds. Movies retains `movies` as canonical compatibility ID; a `media` alias, if ever added, must resolve to it. |
| Utilities and compatibility | Today and AI Assistant/Command are utility/subview surfaces, not ninth/tenth worlds. Shortcuts, Productivity, Notes and legacy Projects remain reachable through utility/linked or nested routes. The existing `projects` alias continues to lead to Work Projects where applicable. |
| Submodules and data owners | Each visible portal targets a dedicated submodule route or an honest unavailable state. Work owns projects/work items/tasks; Notes owns notes; Productivity owns generic task/timer/countdown state; Shortcuts owns shortcut records. Projects & Notes aggregates Work and Notes data and does not create a duplicate store. Games and Movies keep their current domain stores; other families use the owner documented for each module in R4/R5. Detail IDs resolve through their owner and deleted/orphan IDs show an honest state. |
| Routes/history | R1 defines a deterministic world/submodule/detail route registry layered on current `goToPage` and `orbit-page`. Hash deep links are planned because the static server can serve the single HTML file without fallback routing; route parsing normalizes aliases, validates identifiers, updates active parent and title, supports reload/Back/Forward and preserves legacy stored page values. A route transition must not write domain data. Unknown routes resolve to a safe recoverable state. |
| Scenes/assets | Scene registry maps each world to its own production `assets/scenes/<world>/` family, provenance/license metadata, layer roles, loading state, fallback and Full/Subtle/Off/reduced-motion modes. Reference composite images remain only in `docs/ui-reference/`. |
| Data honesty | Every dynamic value is `LOCAL_CORE`, `LOCAL_DERIVED`, `USER_ENTERED`, `OPTIONAL_PROVIDER` or `FUTURE_DISABLED`. No fabricated weather, health/device/account, friends or media availability claims. Empty/loading/error/unavailable states are explicit. Optional provider failure degrades only optional enrichment. |
| Storage and migrations | Preserve localStorage keys, validators, rejected-write semantics and backup v4 initially. Introduce a versioned, non-destructive migration only for a demonstrably necessary new persisted shape; add old-version fixtures and rollback/import proof before shipping. No migration is authorized by R0 itself. |
| Failure isolation | World/scene asset failure leaves the UI usable with deterministic CSS fallback. A submodule failure cannot hide the shell or corrupt owner data. Route, storage and provider failures have truthful feedback. Feature flags are unnecessary for the R0 record; R1 may add one only with a defined rollout/recovery need. |
