## 3. Product hierarchy

The synchronized model is four levels:

1. Global OneSpace shell.
2. Eight main worlds.
3. Dedicated submodule UI surfaces for major portal cards.
4. Detail/create/edit/task surfaces where meaningful workflows require them.

A portal is not complete because it merely navigates. Its target UI must exist and satisfy the functional/verification contract.

`Work → Projects` is the mandatory nested-experience pilot before broad submodule replication.

## 5. Cinematic contract

Preserved lifecycle:

```text
ENTRY / WAKE-UP
→ SETTLE
→ AMBIENT / ALIVE
→ EXIT / RESET
```

Full entry remains approximately 2–5 seconds. Full / Subtle / Off / reduced-motion behavior remains mandatory.

Motion must come from the atmosphere and objects implied by the matching reference; a recycled space/starfield/particle scene is not acceptable.

The eight worlds share one warm premium OneSpace visual family, but each has a distinct subject/scene identity.

## 6. Main-world vs compatibility surfaces

`Today` and `AI Assistant / Command` are utility/subview concepts unless separately approved as full worlds.

Shortcuts, Productivity, Notes and the legacy Projects alias remain functional/reachable compatibility surfaces. They are not extra ninth/tenth/etc. reference-led cinematic worlds.

## 7. Data/storage ownership

Canonical ownership is preserved:

- Work owns Work/project lifecycle records.
- Notes owns note records.
- Productivity owns generic task/timer/countdown state.
- Shortcuts owns shortcut records/settings.
- Home aggregates canonical owners.
- Projects & Notes aggregates/routes canonical Work-project and Notes data; it does not create parallel stores.
- Home `Media & Games` is visual grouping only and must expose separate Games and Movies & Series destinations.
- Existing `movies` compatibility is retained; `/media`, if introduced, is alias-only.

## 8. Data honesty

Every dynamic reference-derived value is classified as one of:

- `LOCAL_CORE`
- `LOCAL_DERIVED`
- `USER_ENTERED`
- `OPTIONAL_PROVIDER`
- `FUTURE_DISABLED`

Weather, HRV, sleep, stress, friends online, device state, smart-home state, account/billing, Premium tier, new releases, AI results and similar screenshot values must never be fabricated merely to match the concept.

## 9. Provider reconciliation

Core OneSpace is local-first and credential-free by default.

Bundled/local data is the normal production path for Movies & Series, Games and Explore.

TMDB / RAWG / IGDB / destination-provider integrations are optional only when explicitly approved/configured. Missing credentials do not block the credential-free release.

Provider security/live-vs-mock verification remains conditional whenever an optional provider actually exists.

## 10. Asset-rule reconciliation

The old `SVG/CSS only / no new binary assets` rule is superseded for the approved redesign.

Properly licensed repository-local raster/vector/media assets are allowed alongside CSS/SVG/procedural layers.

Requirements retained:

- provenance/license/attribution;
- role-appropriate sizing/cropping;
- deterministic fallback;
- no unlicensed/scraped media;
- no core remote-hotlink dependency.
